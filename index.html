Courier Inbox — multi-tenant guide (React)

Send a tenant-scoped inbox message with the REST API, then render it with @trycourier/courier-react. Replace YOUR_ENV_API_KEY with your environment's API key. The live inbox on the right is signed in as multitenant-demo-user — switch tabs to change the tenant.

⚠️ Gotchas (the stuff that trips everyone up)

  • The tenant must exist — create it with PUT /tenants/{id} before you scope anything to it.
  • The user must be a member of the tenant — PUT /users/{id}/tenants/{id}.
  • Scope the send with to.context.tenant_id — that value becomes the inbox accountId the SDK filters on.
  • The tenantId you pass to signIn() must exactly match the tenant_id you sent with.
  • Never ship your API key to the browser — mint a short-lived JWT on your backend and pass that to signIn().
  1. 1

    Create the tenant

    A tenant is the org/workspace a message is scoped to. Create it first — you can't scope to a tenant that doesn't exist.

    Must exist before you send 
    curl -X PUT https://api.courier.com/tenants/acme \
  -H "Authorization: Bearer YOUR_ENV_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"Acme Corp"}'

  2. 2

    Add the user to the tenant

    Create the membership so the user can receive this tenant's notifications. (Creates the user profile if it doesn't exist yet.)

    User must be a tenant member 
    curl -X PUT https://api.courier.com/users/multitenant-demo-user/tenants/acme \
  -H "Authorization: Bearer YOUR_ENV_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
    API reference → · Console: Tenants ↗
  3. 3

    Send a tenant-scoped inbox message

    Put the tenant in to.context.tenant_id and route to the inbox channel. That tenant_id is what the inbox stores as accountId.

    Scope via to.context.tenant_id 
    curl -X POST https://api.courier.com/send \
  -H "Authorization: Bearer YOUR_ENV_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "message": {
      "to": { "user_id": "multitenant-demo-user", "context": { "tenant_id": "acme" } },
      "content": { "title": "Welcome to Acme Corp", "body": "Your Acme inbox is live." },
      "routing": { "method": "single", "channels": ["inbox"] }
    }
  }'
    API reference → · Console: Message logs ↗
  4. 4

    Mint a JWT for the user (backend)

    The browser authenticates with a short-lived JWT, not your API key. Mint it server-side. The token is tenant-independent — one token works for every tenant tab.

    Never expose the API key client-side 
    curl -X POST https://api.courier.com/auth/issue-token \
  -H "Authorization: Bearer YOUR_ENV_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "user_id:multitenant-demo-user inbox:read:messages inbox:write:events",
    "expires_in": "1h"
  }'
    API reference → · Console: API keys ↗
  5. 5

    Render the inbox in React

    Render <CourierInbox/> and sign in with useCourier().auth.signIn, passing the JWT + the same tenantId you sent with. Omit tenantId for the raw, unscoped feed (the “Raw” tab).

    tenantId must match the sent tenant_id 
    import { useEffect } from "react";
import { CourierInbox, useCourier } from "@trycourier/courier-react";

function Inbox({ jwt }) {
  const { auth } = useCourier();

  useEffect(() => {
    auth.signIn({
      userId: "multitenant-demo-user",
      jwt,                // minted by your backend (step 4)
      tenantId: "acme",   // omit for the raw feed (all tenants)
    });
  }, [jwt]);

  return <CourierInbox />;
}
